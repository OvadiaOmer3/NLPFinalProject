# token_strain/ — does token interference explain forgetting on top of exposure?

**Question.** Does a fact get forgotten because its tokens are shared with many
*other entities* the model saw in training (token strain / ownership), beyond
what raw exposure and name length already explain?

**Write-up:** [`FINDINGS_token_strain.md`](FINDINGS_token_strain.md) — conclusion,
method, results, caveats. Every number in it is regenerated by
`strain_diagnostics.py`; `report_token_strain.py` only renders that JSON.

| file | role |
|---|---|
| `strain_models.py` | model spec (`BASE`/`NAMELEN`/`STRAIN`/`F1`/`F2`, `LR`) + `prepare` + `fit`. **Library only, no CLI** — the single source of truth for *what* is fitted |
| `strain_diagnostics.py` | **the one entry point that fits models.** Regenerates every diagnostic → `data/artifacts/features/strain_diagnostics_specE.{txt,json}` |
| `null_control_distribution.py` | permutation test: reshuffle which tokens belong to which entity, N times, and locate the real index in that null (`run_permutations` is what the diagnostics call) |
| `report_token_strain.py` | figures for the findings doc (fits nothing; reads the diagnostics JSON) |
| `plot_token_strain_permutation.py` | appendix figure: the permutation null as a PDF |
| `plot_accuracy_trajectory.py` | accuracy-vs-checkpoint plot of the recall sweep |

Shared code this uses: `src/features/strain.py` (EntityUniverse, TokenIndex,
WindowMap; tests in `tests/test_strain_features.py`) and
`feature_extraction/build_strain_panel.py` (builds the (fact × window) panel).

**Data read** (all committed): `data/artifacts/features/strain_panel_15shot_top10.parquet`,
`data/artifacts/features/strain_diagnostics_specE.{txt,json}`, and the recall sweep
`data/artifacts/expermints/15shot_trajectory_top10_internal_with_hidden/recall/`
it was built from.

## Pipeline (CPU only)

Consumes a recall sweep from `feature_extraction/eval_checkpoints.py` plus
`popqa-kas` and the six per-epoch batch indices. No GPU, no hidden-state dumps.
Run everything from the repo root.

```bash
# 0. The recall sweep (GPU; the same command as run (4) in
#    neuron_forgetting/02_internal_paper_figures.ipynb). --top-shared-chunks-pct 10 keeps the top
#    decile of popqa-kas by shared chunks: 1,452 facts after the 16 few-shot subjects
#    are dropped, the same ids as the committed parquets. --no-hidden skips the
#    hidden-state dump, which token strain does not use.
#    Decoding is not bit-reproducible across reruns: a second run of this sweep
#    (recall/original_corpus/LMEnt_HF_models/15shot_top10pct_trajectory_1B-6E/recall_only) gives identical prompts but flips `correct`
#    for a small fraction of facts, which shifts the strain estimates slightly. The
#    paper's exact numbers therefore come from the committed parquets, not a rerun.
STEPS="50000 100000 150000 200000 250000 300000 350000 400000 450000 500000 550000 600000 658032"
python feature_extraction/eval_checkpoints.py --num-shots 15 --no-hidden \
    --steps $STEPS --top-shared-chunks-pct 10 \
    --output-dir data/artifacts/expermints/15shot_trajectory_top10_internal_with_hidden

# 1. Build the (fact x window) panel.  --recall-dir pivots a sweep directly;
#    --trajectory takes a wide CSV (id + one column per checkpoint step) instead.
python feature_extraction/build_strain_panel.py \
    --recall-dir data/artifacts/expermints/15shot_trajectory_top10_internal_with_hidden/recall \
    --out data/artifacts/features/strain_panel_15shot_top10.parquet
#   --df-cutoff 400   drop tokens carried by more than N entities (-1 keeps all).
#                     400 removes exactly {the, of} on popqa-kas; there is no clean
#                     gap below that, so a lower cutoff also deletes `john`/`david`.
#   --bpe             tokenize with the model tokenizer instead of whitespace words
#                     (implemented, not yet run -- re-derive the cutoff if you use it)
#   --idf             IDF-weight shared tokens instead of counting them

# 2. (nothing to run -- strain_models.py is a library. The model comparison it
#     used to print is section 2 of the diagnostics in step 4.)

# 3. (nothing to run -- the permutation test is section 10 of step 4, which calls
#     null_control_distribution.run_permutations and saves every draw of the
#     reported test in its JSON. The standalone script is still there for ad-hoc
#     runs on other panels; if you use it, ALWAYS pass --control-namelen: without
#     it the baseline is exposure-only, where scrambled strain still proxies name
#     length, so both the real and the scrambled feature beat it for the same
#     uninteresting reason.)

# 4. Every diagnostic quoted in the findings doc, as a saved log + JSON mirror.
#    Run this before the figures -- the report reads its JSON and fits nothing.
#    Drop --permutations for a seconds-long run; 150 takes ~6 min (3 specs).
#    Needs statsmodels (see requirements.txt).
python token_strain/strain_diagnostics.py \
    --panel data/artifacts/features/strain_panel_15shot_top10.parquet \
    --out data/artifacts/features/strain_diagnostics_specE.txt \
    --permutations 150

# 5. Figures (reads step 4's JSON for every model number and the permutation
#    histogram, and the panel for the descriptive plots).
#    --cdn gives a ~60 KB page instead of ~4.8 MB, but needs a network to view.
python token_strain/report_token_strain.py \
    --diagnostics data/artifacts/features/strain_diagnostics_specE.json \
    --panel data/artifacts/features/strain_panel_15shot_top10.parquet \
    --out data/artifacts/features/report_token_strain_specE.html
```

The rendered HTML / PDF figures are **not** kept in the repo (gitignored under
`data/artifacts/features/`); regenerate them from step 5 when you want them.

There is **one entry point that fits these models**: `strain_diagnostics.py`.
`strain_models.py` is a library with no `main()`, `null_control_distribution.py`
fits only permutation replicates (and exposes that loop as `run_permutations`,
which the diagnostics calls rather than copying), and `report_token_strain.py`
fits nothing. Section 3 of the diagnostics additionally *asserts* that its
"current" comparison spec reproduces `BASE` verbatim, so a change to the
specification cannot silently leave a stale robustness table behind -- it fails
with a diff.
